# v0.19.24 bounded direct-speed development study

## Declaration before new payload inspection

This is a diagnostic, not an adopted feature or a new training population.
The owner-pushed source, exact private request/helper and this protocol need
independent GO, exact-head three-job CI and merge before the owner operation.
That normal review cycle externally freezes the design before new payloads.
Do not execute the study while implementing or reviewing source on copies.
Synthetic MCAPs are permitted for engineering checks. Final outings stay closed.

Bind the original sealed development experiment and its unchanged native
role/history/archive/row/fold validator. The private request names exactly two
other development outings, one recording each. Exclude the previously examined
outing. The issued request uses the first two other outing IDs in sorted order
whose original registered raw size is at most 4 GiB, using metadata only.
No replacement outing is permitted after any affordability or payload outcome.
Newly reported recordings are outside this experiment and this study.

For each named recording choose the earliest sustained geometry run using the
unchanged v0.19.20 `fixed_window_start`: geometry availability, original message/
pair adjacency, increasing source time with gaps at most 200 ms, nondecreasing
log time, and at least 12 seconds of source/log span. Select the half-open
12-second log window starting there. Decode both direct topics only inside a
one-second-padded log window, using existing indexed planning/CRC decoding.
Window selection must not use speed flags, residual values, clock-age outcomes
or model scores. No extra window, age tuning, offset fit or broad scan fallback.

## Frozen selection and outcomes

Reuse the unchanged v0.19.21 primary selector: select the latest update with
strictly earlier log time once; then screen positive source time, source at or
before EDP, age at most 100 ms, positive publish time at or before the recorded
EDP publish time, inner qualifier 1, finite value and nested presence. Duplicate
latest log times fail. Never search older updates after a failed screen. Retain
geometry and all declared `estimate_features_*` exclusions and original resets.
Always report the v0.19.22 strict-source secondary on this same selected update.
Outer/standstill qualifiers remain observed separately, not substituted for the
inner qualifier or silently adopted. Negative values are reported explicitly;
they do not change the frozen selector and need semantic assessment.

For every topic/window report all candidates, geometry/no-estimate-failure
stratum denominator, original complete rows, primary/secondary coverage,
failure-code counts, gained/lost rows, and complete run-length/span lists.
Report the original, primary and secondary sequence distributions using the
same recording/message/pair/source-gap resets. Do not join windows or outings.
The predeclared practical temporal target is primary stratum coverage at least
95% and a run spanning at least 5 seconds in each named window; report whether
it is met per topic/window. This is a diagnostic usefulness target, not proof
of adequate training histories, feature validity or cohort-wide recovery.

On originally complete rows passing each rule, compare selected direct value
against the accepted old speed column: paired count, mean difference, RMS
difference, maximum absolute difference, old/direct ranges and maximum absolute
difference divided by the observed combined range (null for zero range).
Use provisional engineering concern thresholds of absolute mean difference
0.5 m/s, RMS difference 1 m/s, maximum absolute difference 3 m/s; equality to a
bound passes. These are declared triage tolerances, not calibrated sensor
accuracy, semantic equivalence, a model admission gate or an adoption rule.
No pairs means unassessable, never agreement. Report both topics and both rules
without choosing the better result. Direct longitudinal speed and displacement
magnitude can differ with motion/reference point; agreement cannot prove the
same physical quantity. Source/publish/log checks do not prove consumer timing.

## Small cached population check

Only after the same source/review gate, use existing accepted numeric geometry
and original candidate identities for all development outings. Compare original
matched-complete versus geometry-with-only-future-speed-failure rows, per outing
and each fixed H100 station: count, mean, population standard deviation, RMS,
and future-only minus complete mean. No pooled frame-level inference, p-values,
new normalization, fitting or model ranking. Report missing classes explicitly.
Describe retained-candidate complete-mask run lengths and message-index spacing
within each recording; do not claim a physical deterministic beat from this.
Other failures stay outside this two-group comparison with explicit counts.
Non-speed values for incomplete rows are reported unavailable unless actually
present in the frozen archive; do not acquire raw data to fill that omission.
No residual arrays are exported. This describes possible population shift; it
cannot prove selection independence, representativeness or effects on old fits.

## Resource, integrity and lifecycle boundary

Maximum two raw files, 4 GiB each and 6 GiB total. Hash each complete original
file once with a separate 120-second bound; this isolated study raises only
the old pilot's 2 GiB identity-hash size ceiling. All indexed decoder limits
are reused unchanged per window: 120 seconds processing including planning,
128 MiB metadata and 128 MiB selected chunk reads, 512 MiB expansion, 4 MiB
single chunk, 2,048 selected chunks, 50,000 advertised/decoded selected messages,
32 MiB index database. Keep at least 1 GiB available RAM and 256 MiB scratch.
Preflight both files using metadata/indexes before claiming/hash/payload.
Affordability failure is inconclusive, with no replacement or larger fallback.

Validate live merged-main, runtime, exact-head CI and owner-attested independent
GO before raw path stat/resolve/open or population statistics. Reject output
inside accepted immutable inputs. Keep one descriptor per raw from planning
through identity hash/decode; require unchanged file identity throughout.
Durable canonical per-window claims omit transport/output paths and JSON
formatting; claim all named windows before hashing the first. Any started
window blocks renamed/rebatched repeats. Preserve partial claims/reports and
unknown phase progress after termination. No claimed design may be retried by
editing the request. Revalidate watched inputs and source before completion.

Output private reports, pinned metadata evidence, selected velocity updates,
frame decisions, population station summaries, sequence lists and Matplotlib
PNG/PDF figures. No new X/Y archive, schema amendment, raw registry admission,
speed-policy adoption, model fitting or final evaluation. The private owner
launcher packages complete or partial evidence with child exit status. After
return, the main agent evaluates all outcomes and decides whether a versioned
feature/population comparison is justified; no automatic refits follow.
