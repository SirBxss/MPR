# Direct speed metadata recovery

2 November 2026. PR #49 is merged with its approved source tree. Independent
source, protocol and exact private launcher GO and the required CI are accepted.
The first owner operation returned a normal metadata preflight failure before
any study claim, complete file hash, velocity payload decode or population
comparison. The private returned archive and receipts are preserved.

The study wrapper traversed the schema group again after the original indexed
planner had already constructed its decoders. That unnecessary traversal could
exhaust the existing metadata read ceiling on schema heavy files. The correction
passes the existing descriptor observer into the original construction traversal.
Validation uses the very same selected schema objects used to construct the
decoders. Inventory integrity, explicit field and qualifier checks, indexed
planning, CRC checks and every resource limit remain in force.

The optional observer is a keyword argument on prepare_window. Its default path
uses the original decoder call unchanged. The direct speed wrapper supplies its
existing validation callback and records one decoder schema traversal. This does
not mean the separate inventory integrity passes are omitted. Original reader
consumers, scientific selectors, masks, comparisons, sequence resets and model
code retain their existing behaviour.

Keep the original scientific study revision and exact request. Outings, windows,
padding, topics, source conventions, source age, publish and validity screens,
diagnostic targets and speed tolerances are unchanged. The same canonical claim
keys remain in use. A fresh launcher may continue only after verifying the exact
returned failure and reconciling actual existing claims. It must refuse any
uncertain prior claim or a prior claim on either selected raw identity across
diagnostic revisions. It never deletes or renames the original attempt.

The private recovery launcher binds the previous ZIP, source, review, request,
normal child failure and zero claim/hash/payload phase evidence. It checks the
owner claim ledger again before operation, uses a fresh attempt and source seal,
and returns the prior ZIP with the new complete or partial evidence. Parent
SIGTERM and SIGHUP handling now terminates the separate child group and attempts
publication, as the existing Ctrl+C and timeout paths do. SIGKILL or power loss
still leaves unknown progress and requires evidence preservation.

The correction and exact replacement launcher require independent delta review,
new actual head CI and owner merge before the single continuation command.
An unstarted metadata failure is not a speed feasibility result. This step
creates no recovered training population, feature adoption, model fit or new
drive intake. The original scientific candidate declaration remains binding.
